# Decisions Log

Записываю ключевые решения по ходу разработки Raschod (трекер расходов
с трением) с кратким обоснованием. Полный дизайн — в
`docs/superpowers/specs/2026-09-14-raschod-design.md`.

## 2026-09-14 — Платформа: React Native + Expo (EAS Build)

Разработка ведётся агентом в терминале на Windows, без Mac. Только
Expo + EAS Build даёт возможность собрать iOS-бинарник в облаке без
локального Xcode/Mac. Один код на TypeScript под iOS и Android, EAS
Submit публикует в оба стора из CLI.

## 2026-09-14 — v1 без backend, полностью local-only (SQLite)

Изначально планировался Supabase (managed Postgres + Auth) для логина
и синхронизации. Пользователь не знаком с облачными сервисами и не
хочет заводить внешний аккаунт сейчас. Решение: v1 хранит всё на
устройстве через SQLite (expo-sqlite + Drizzle ORM), без логина.
Слой данных изолирован через repository-интерфейсы — облачный sync
добавляется в Phase 3 без переписывания features/UI.

## 2026-09-14 — Геймификация как часть v1, не Phase 2

Изначально геймификация (стрики/бейджи) была в Phase 2. Пользователь
явно попросил продумать её тщательно и сделать интересной сразу — она
двигает саму механику трения (opportunity-cost нотис "на N% ближе к
цели"), так что часть геймификации (счётчик "сэкономлено трением",
XP, режим цели) переехала в MVP-scope, а остальное (челленджи, бейджи,
уровни-косметика) — тоже в v1, лёгкая механика без денег в наградах.

## 2026-09-14 — Entitlements-слой с первого коммита

Требование пользователя: архитектура должна поддержать подписку позже
без переписывания. Решение: с первого коммита есть `core/entitlements`
с захардкоженным планом `free` — фичи уже проверяют флаг, реальный
paywall (RevenueCat) подключается в Phase 2 заменой одной реализации.

## 2026-09-14 — Мультивалюта без live-конвертации

Пользователь пользуется несколькими валютами (RUB/BYN/PLN/USD).
Live-курс через внешний API — ещё один сторонний сервис и лишняя
сложность для v1. Решение: ручной ввод курса пользователем, хранится
per-transaction.

## 2026-09-14 — Работа напрямую в `main`, без веток/worktree

Пользователь явно делегировал git-процесс ("гит делай на свой вкус,
ничего не спрашивай") и описал ожидаемый воркфлоу как прямые коммиты
после каждого куска функциональности — про ветки/PR речи не было.
Соло-проект, конфликтовать не с кем. Ветка потребовала бы отдельного
решения "смержить обратно" — а это уже действие с сайд-эффектом наружу,
которое по правилам агента требует отдельного разрешения. Работа прямо
в `main` эту развилку не создаёт вообще.

## 2026-09-14 — Атрибуция коммитов стандартизирована на "Claude Sonnet 5"

Часть коммитов, сделанных подагентами на модели Haiku, самоподписались
как "Claude Haiku 4.5" (своей собственной моделью) вместо направленной
для этой сессии атрибуции; один коммит вообще остался без подписи.
Обнаружено и исправлено (`git filter-branch` по ещё не запушенному
диапазону) до первого пуша — теперь везде единообразно
`Co-Authored-By: Claude Sonnet 5`.

## 2026-09-14 — Plan 1 "Foundation & Domain Layer" завершён

14 задач по TDD (subagent-driven-development), ревью на каждом шаге,
финальный ревью всей ветки (opus) + один fix-wave по его находкам.
Итог: 65 тестов, lint/typecheck чистые, запушено в `origin/main`
(`a8815cd`). По пути починены 2 реальных бага, найденных ревью, а не
самой разработкой: тихо падавший typecheck (не было jest-типов в
tsconfig — открылось только когда появились тестовые файлы) и
скрытый баг с несидированными category id в тестах транзакций
(вскрылся, когда включили реальную проверку внешних ключей вместо
самопального отключения). Два дизайн-решения сознательно отложены до
следующего плана (экранов), а не угаданы сейчас: связь
`frictionLevel` (хранится) ↔ `FrictionTier` (домен), и политика
единственной "основной" цели (auto-demote / throw / решает UI).

Дальше — отдельный план "Screens & Navigation": экраны, дизайн-система
на базе revolut/wise (awesome-design-md) + frontend-design + taste,
NativeWind, анимации. Это уже не архитектурная развилка (стек и
данные зафиксированы), просто следующий кусок работы по той же spec.

## 2026-09-14 — Дизайн-система: токены (референсы revolut/wise, не копия)

Прочитал `revolut/DESIGN.md` и `wise/DESIGN.md` (awesome-design-md) —
оба про маркетинговые сайты (hero-band, footer, plan-card), не про
мобильный продуктовый UI, поэтому беру не компоненты, а принципы:
- Revolut: высокий контраст тёмного/светлого канваса, pill-кнопки,
  жёсткая типографика без лишних декораций, скупой acccent-цвет.
- Wise: один яркий brand-accent (не палитра из десяти), крупный
  radius на карточках (не sharp corners), дружелюбный, не банковский.

Raschod — не финтех-бренд с наследием, поэтому не копирую ни один
токенсет один-в-один. Решение (для Plan 2, "Design System Foundation"):
- **Accent**: один яркий акцент (обсуждается в Plan 2 — кандидат:
  тёплый лайм/мятный на тёмном канвасе, ассоциация "рост/накопление",
  не банковский синий-по-умолчанию).
- **Radius**: крупный (16–24px) на карточках/модалках трения — мягче,
  менее "банковский", подходит для "дружелюбного давления", не
  наказания.
- **Тёмная тема — основная** (Revolut-подход), светлая — зеркальная
  пара, обе через системную настройку (решено ранее).
- Типографика: системный шрифт (SF Pro/Roboto через RN default) —
  не тащим платный/проприетарный шрифт (Aeonik Pro / Wise Sans) ради
  чистоты лицензии и веса бандла; жирный display-вес (700-800) для
  крупных чисел (баланс, прогресс цели) — единственное "громкое" место.
- Кнопки: pill-shaped (rounded.full) — из Revolut.
- Elevation: без теней, через цветовые слои (canvas → surface →
  elevated) — из обоих референсов, современнее чем classic drop-shadow.

Точные hex/px значения — в Plan 2 spec addendum, не здесь (DECISIONS.md
для обоснований, не для токенов).
