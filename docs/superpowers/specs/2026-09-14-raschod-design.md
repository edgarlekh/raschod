# Raschod — Трекер расходов с трением — Design Spec

Date: 2026-09-14
Status: Approved (user go-ahead 2026-09-14)

## Purpose

Mobile-first приложение личных финансов, где ключевая механика —
"трение" при трате: чем больше сумма, тем больше уточняющих вопросов
приложение задаёт перед тем как засчитать трату, помогая понять нужна
ли она и приближает ли к финансовой цели ("мечте"). Цель — продукт
уровня, который не стыдно продавать по подписке (Revolut/Monzo/YNAB
класс UI и полировки), а не пет-проект.

## Non-goals (v1)

- Банковская синхронизация (Plaid-подобная) — отдельный compliance-трек,
  не сейчас.
- Реальный платёжный процессинг — только структура под него.
- Соцфичи (шаринг, друзья) — не запрошено, лишняя сложность.
- Live-конвертация валют через внешний API — ручной курс в v1.

## Platform & Stack

- **Expo (React Native) + TypeScript**, Expo Router (файловый роутинг).
- **State**: Zustand.
- **Persistence**: SQLite (expo-sqlite) + Drizzle ORM, версионированные миграции.
- **Animations**: Reanimated 3 + Moti, expo-haptics.
- **Styling**: NativeWind, дизайн-токены на основе `revolut/DESIGN.md` и
  `wise/DESIGN.md` (awesome-design-md), доработано через ui-ux-pro-max и
  frontend-design skills, ревью через taste skill.
- **Charts**: react-native-gifted-charts.
- **Testing**: Jest + React Native Testing Library (unit/component),
  Maestro (E2E).
- **CI**: GitHub Actions — lint + typecheck + test на каждый push.
- **Build/publish**: EAS Build + EAS Submit → App Store + Play Market.
- Репозиторий: `github.com/edgarlekh/raschod`, один репо (нет backend —
  v1 полностью local-only).

## Why local-only (no backend) in v1

Пользователь не знаком с облачными сервисами (Supabase и т.п.) и не
хочет создавать внешние аккаунты сейчас. Решение: все данные хранятся
на устройстве (SQLite), без логина/пароля. Архитектура изолирует слой
данных через repository-интерфейсы, так что облачный sync — опциональная
фича Phase 3, добавляется без переписывания features/UI.

## Architecture

```
app/          — экраны (Expo Router), только презентация
features/     — по фиче: transactions, goals, categories, friction, analytics, gamification
domain/       — чистая бизнес-логика, без I/O, 100% юнит-тестируема:
                - движок трения (сколько и какие вопросы по сумме)
                - расчёт прогресса цели
                - расчёт opportunity-cost ("на X% ближе к цели")
                - XP/уровни, стрики, бейджи
data/         — repository-интерфейсы (TransactionRepository, GoalRepository,
                CategoryRepository, GamificationRepository) + SQLite-реализация
db/           — Drizzle-схема, миграции
core/         — entitlements/feature-flag сервис (free/premium стаб —
                под будущую подписку без переписывания)
```

Поток данных: UI → хук фичи → domain-логика → repository → SQLite.
Domain-слой чистый (без I/O) — тестируется без БД и без UI.

**Обработка ошибок**: repository кидает типизированные ошибки, UI
показывает toast/инлайн-сообщение. Миграции БД версионированы с
откатом. Движок трения при неоднозначности **по умолчанию спрашивает
больше, не меньше** — соответствует цели продукта (лучше лишний вопрос,
чем пропущенная импульсивная трата).

## Feature set

### MVP (v1)
1. Онбординг: валюта, первая цель (можно пропустить)
2. Добавление транзакции (доход/расход, сумма, категория, заметка)
3. Движок трения:
   - < 5 у.е. эквивалента — 0 вопросов
   - 5–30 — 1 вопрос ("точно надо?")
   - 30–100 — 2 вопроса
   - 100+ — вопросы по теме категории траты + **opportunity-cost нотис**:
     "Пропустишь эту трату → на N% ближе к цели [название]" — процент
     считается от суммы, которая осталась до цели; если целей
     несколько — берётся приоритетная (ближайшая к завершению или
     явно отмеченная пользователем как основная)
4. Категории: дефолтный набор + кастомные (иконка, цвет)
5. Цели: создание (имя, сумма, дедлайн опционально), анимированный
   прогресс-бар, ручное/авто пополнение из "сэкономленного трением"
6. История с фильтрами (категория/период/тип)
7. Главный экран: баланс, быстрый ввод, активная цель, последние операции
8. Тема свет/тёмная (по системной настройке)
9. Мультивалюта (стартовый набор RUB/BYN/PLN/USD + добавление своих),
   ручной ввод курса, базовая валюта в настройках
10. Локальное хранение (SQLite), без логина/аккаунта

### Gamification (v1, часть core-предложения, не Phase 2)
11. **Режим цели / "путешествие"**: активная цель отображается как путь
    с вехами, аватар/иконка двигается по пути по мере накоплений;
    включается в настройках (не навязывается всем)
12. **XP и уровни**: очки самоконтроля за пропущенные импульсивные
    траты (подтверждённый отказ после вопроса трения); левелап
    открывает косметику (иконки приложения, темы) — без денежных наград
13. **Стрики**: дни без импульсивных трат / в рамках бюджета
14. **Еженедельные челленджи**: опциональные, генерируются из
    собственных трат пользователя (например "неделя без кафе" — если
    кафе триггерит вопросы трения чаще всего)
15. **Бейджи**: витрина ачивок (первая закрытая цель, 30-дневный
    стрик, N пропущенных импульсивных трат и т.д.)
16. **Счётчик "сэкономлено трением"**: анимированный, на главном
    экране, растёт с каждым подтверждённым отказом от траты

### Phase 2
17. Аналитика: круговая по категориям, тренд по времени, месячная сводка
18. Бюджеты по категориям
19. Регулярные платежи/подписки — трекинг
20. Экспорт CSV
21. PIN/biometric лок приложения
22. Локальные push-напоминания (бюджет на исходе, забыл внести трату)
23. Реальный paywall (RevenueCat) поверх готового entitlements-слоя из v1

### Phase 3
24. Облачный sync/бэкап (опциональный логин)
25. Виджеты на экран
26. Несколько кошельков/счетов
27. Продвинутые инсайты/аномалии
28. Соцфичи — только по запросу

## Testing & Process

- TDD по юнитам: domain-логика (пороги трения, XP-математика, расчёт
  прогресса цели, opportunity-cost) — тест сначала, потом код.
- Repository-тесты — на тестовой/in-memory SQLite.
- Компонентные тесты ключевых экранов (добавление траты, модалка
  трения, экран цели).
- Maestro E2E на критический путь: добавить трату → вопрос трения →
  обновление прогресса цели/XP.
- Bulletproof-цикл (research → design → tests → impl → review → verify)
  на каждую нетривиальную фичу.
- Ревью перед закрытием каждого этапа implementation plan
  (requesting-code-review / receiving-code-review).
- `DECISIONS.md` — лог обоснований ключевых решений, обновляется по ходу.
- Коммиты — Conventional Commits (`feat:`, `fix:`, `chore:`, `test:`),
  после каждого законченного куска функциональности.
- Прогресс фиксируется в git + `DECISIONS.md`, чтобы работа была
  продолжаема из любой новой сессии без потери контекста.

## Monetization-readiness (structural only, no payment integration yet)

- `core/entitlements` — сервис с одним источником правды: "какой план у
  пользователя" (`free` захардкожен как дефолт в v1).
- Фичи, которые в будущем станут premium (безлимит целей, кастомные
  вопросы трения, экспорт, темы, кастомные челленджи), уже проверяют
  флаг из entitlements, а не жёстко зашиты как всегда доступные.
- Когда добавится реальный paywall — меняется только реализация
  entitlements-сервиса (например, интеграция RevenueCat), features его
  не замечают.
